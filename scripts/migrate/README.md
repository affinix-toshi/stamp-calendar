# 過去データの引き継ぎ（旧アプリ → 新アプリ）

旧アプリ（4月から使っている版）の家族ルームのスタンプを、新しいアプリの家族ルームへ写すための道具です。
手元のパソコンでだけ動かします。順番を守ってください（逆にすると、データが2か所に分かれたり消えたりします）。

## 準備

- 鍵ファイル `.secrets/family-sa.json` を置く
  - Firebase コンソール →（歯車）プロジェクトの設定 → サービス アカウント →「新しい秘密鍵を生成」
  - `.secrets/` は Git に入りません。鍵は人に渡さないでください
- 旧アプリの家族ルームのルームコード（英数字5文字。以下 `ABCDE` と書きます）
- 新しいアプリで、オーナー夫婦がログインして家族ルームを作り、2人とも参加しておく。そのルームID（以下 `新ルームID`）

## 手順

### 1. バックアップ

```
npm run migrate:backup
```

旧データ `rooms/` をまるごと `.secrets/backup-YYYYMMDD-HHmm.json`（日本時間）に保存します。
保存した場所と、スタンプの合計数が表示されます。データベースには何も書きません。
**このファイルが「元の正しいデータ」です。消さずに保管してください。**

### 2. 旧ユーザーの一覧を見る

```
npm run migrate:report -- --room ABCDE
```

旧ユーザーIDごとに「名前・押した数・最後に押した日」の表が出ます。
旧アプリは端末ごとにIDを作っていたので、同じ人に複数のIDがあります。
形がおかしくて写せないスタンプがあれば、ここに一覧で出ます。

### 3. 対応表を作る

表を見て「このIDたちは全部トシ」のように決め、`.secrets/user-map.json` を作ります。
手順2の最後に出るひな形をコピーして、`""` の中に新しいアプリの uid を書きます。

```json
{
  "旧ユーザーID1": "トシの新しいuid",
  "旧ユーザーID2": "トシの新しいuid",
  "旧ユーザーID3": "妻の新しいuid"
}
```

- 新しい uid は、新しい家族ルームの参加者（`v2/rooms/{新ルームID}/members`）のものだけ使えます
- 表示名は新しいルームの名前に置きかわります

### 4. お試し（何も書かない）

```
npm run migrate:run -- --from ABCDE --to 新ルームID --dry-run
```

写す件数を月ごとに表示するだけで、何も書きません。
対応表にない旧ユーザーIDや、参加者ではない uid があると、エラーとその一覧が出ます（このときも何も書きません）。

### 5. 本番の書きこみ

```
npm run migrate:run -- --from ABCDE --to 新ルームID
```

- 対応表にもれが1つでもあれば、何も書かずに止まります
- スタンプのIDは旧データのものをそのまま使うので、何回実行しても件数は増えません
- 新しい側にすでに同じIDがあるスタンプは書きません（新しいアプリで付けたメモなどを消さないため）
- 新しいアプリで押したスタンプは消しも上書きもしません（1件ずつの場所に足すだけ）
- 書いた場所（`v2/rooms/新ルームID/stamps/日付/ID`）がすべて表示されます。**この表示はとっておいてください**

### 6. たしかめ

```
npm run migrate:verify -- --from ABCDE --to 新ルームID
```

日付ごとに、旧データの件数と新しい側で見つかった件数を並べます。
旧データのスタンプがすべて、同じ絵文字・名前・押した日時で新しい側にあれば、最後に `OK` と出ます。
足りないもの・中身がちがうものがあれば、その一覧と `NG` が出ます。
新しいアプリで押したスタンプは「比べる対象外」として件数だけ出ます（問題ありません）。

このあと、新しいアプリで4月の月にスタンプが出ているかを目で見て確かめます。

## 写さないもの

- 日付の形がおかしいもの（`YYYY-MM-DD` でないもの）
- 絵文字・名前・押した人・押した日時のどれかがないスタンプ

これらは手順2・4・5・6で一覧に出ます。必要なら、バックアップを見て手で直すか相談してください。

## 元に戻すとき

- 旧データ `rooms/` は読むだけで、変えていません
- 写したものは、手順5で表示された場所（`v2/rooms/新ルームID/stamps/日付/ID`）だけです。
  その場所を Firebase コンソールで消せば、写す前に戻ります（新しいアプリで押したスタンプは別の場所なので残ります）
- 何かおかしいときの正しいデータは、手順1のバックアップファイルです
